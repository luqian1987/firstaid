# 素材台账

收到的检验报告，逐份记：**报告给到了什么、报告没给什么、哪些要用户拍板**。

`板块划分.md` 管「这份稿子排第几」，本表管「这份稿子的料齐不齐」。
两件事不一样：报告收到了，不等于能开写——方法学、参考区间、报告周期
缺哪一样都得先补，**不许拿常识填**（见 `CLAUDE.md` 第二节）。

报告原件放 `input/`，含受检人信息，永不进版本库。本表只记从报告里读到的
**结构性事实**，不记姓名、样本号、送检单位。

## 代谢 03 · 全谱氨基酸代谢风险评估

**收到** 2026-08-27　第 4–9、11–12、14–15 页（用户按页拆开传，一次 5 份，**尚未传完**）
《氨基酸分析评估报告 Amino Acid Analysis Assessment Report》
姓名「测试」、送检单位「测试医院」，是系统生成的演示报告。

### 关键判定：这是空白模板，没有示例值

「实验结果」列全部是 `1` / `11` / `111` / `1111`。
**这不是文件损坏，也不是字体映射出错**——挖到 PDF 内容流字节层面确认过：

- 参考范围列的字节是 `0015 0017 0010 0019 001a` → `24-67`，同一套 CID 编码能完美还原；
- 实验结果列的字节就是 `0014`（数字 1）在重复，1 位数到 4 位数不等。

↑↓ 箭头也是按这些 1 算出来的（肌酸 1 < 24 ↓、谷氨酸 1111 > 178 ↑，33 行全对得上）。
所以是系统把结果位填成了占位符，**报告里没有任何真实示例值**。

按 `CLAUDE.md` 第二节：**「报告模板」那节改成「报告项目与判读阈值」，只列项目和参考区间，
不编造检测值**——和神经 01 一样处理。

> 排查记录：`pdftotext` 会报 `Missing language pack for 'Adobe-GB1'` /
> `Unknown font tag 'KSPF1'` / `premature end of data in flate filter`。
> 这三条都是**噪音**：KSPF1 只用来画页脚的「检验人员/审核人员」四个字。
> 装 poppler-data、换 mutool 都不会改变结果列。别再往这个方向查了。

### 排版思路（页齐后定稿）

33 项用 `.res-wrap.big`，按第 6、7 页的必需 / 非必需 / 半必需三分法做 `tr.grp`
