# 功能医学检测项目速览 —— 工作说明

给客户看的检测项目介绍单页。每个项目 **正好 2 页 A4**，屏幕版 HTML + 送印版 PDF 两套。

已完成 4 份在 `sheets/`，**照着它们写**，不要另起风格。

---

## 一、每次要做什么

用户把检验报告（PDF / docx / 图片）放进 `input/`，然后说做哪几项。你的流程：

1. **读报告**。PDF 用 `pdftotext -layout`，读不出文字层的用 `pdftoppm -r 150 -png` 转图再看。docx 用 `extract-text` 或 `python-docx`。
2. **查名称和价格**。一律以 `项目清单.md` 为准，那是协议附件原文。**不要自己起名，不要自己定价。** 清单里没有的，停下来问用户。
3. **写 sheet**。在 `sheets/` 下新建 `NN_系统NN_项目名.html`，只写 `<div class="doc">…</div>` 片段，不要写 `<html>` `<style>`。
4. **加进 manifest**。`sheets/manifest.txt` 一行一个文件名，顺序就是成稿顺序。
5. **构建**。`python build.py 项目名` —— 脚本会逐份校验是不是 2 页，不是就报错。
6. **自查**。`pdftoppm -f 1 -l 2 -r 60 -png out/送印_XXX.pdf /tmp/qa` 然后用 Read 工具看图，确认没有溢出、错位、色块跑偏。**每次都要看，不要跳过。**

## 二、内容纪律

**这是最重要的一节。**

- **数值、参考区间、阈值、方法学、样本类型，一律来自报告原文。** 报告里没有的就写「待补」，不要推断、不要用常识补。
- **示例数据用报告里的真实示例值。** 如果报告是空白模板（没有示例值），就把「报告模板」那节改成「报告项目与判读阈值」，只列项目和参考区间，**不要编造检测值**。神经 01 就是这么处理的。
- **报告周期只有一个样本的日期差时，写「报告周期待补」**，不要拿单个样本反推标准周期。
- 「科学依据」三条必须能在报告原文或报告自带的参考文献里找到出处。最后一条固定是免责：这是风险/状态评估，不作为诊断依据。
- 疾病风险表述要留余地：「风险相关标志物」「提示风险增加」，不写「会得××病」。

## 三、版式结构

固定六节，序号可微调（指标多的可以把「报告模板」提前到第 2 节）：

```
1 临床意义      一段 lead，破题 + 机制 + 和常规检查的分野
2 适合人群      .who，9 或 12 项（3 列网格，必须是 3 的倍数）
3 报告模板      表格 + .dnote 解读 + 可选 .tiers 三档
4 与相关检查的区别  .vs，正好 3 项
5 可以做什么     .acts，正好 3 栏，每栏一个两字动词
6 常见问题      .faq，正好 3 组
科学依据        .evi，3 条
免责声明        .endnote
```

页 1 装 1–3 节，`<div class="pbreak">` 断页，页 2 装 4–6 节 + 依据 + 免责。

### 组件速查

| 类 | 用途 |
|---|---|
| `.doc` | 一个项目的整体容器 |
| `.mast` | 页眉：`项目说明 系统 · 子类` + `编号 版本 2026-08 · 第 1 页 / 共 2 页` |
| `.hero` | 标题区。`.l` 放分类/h1/英文名/一句话，`.r` 放价格和样本信息 |
| `.pv` | 价格。`¥1680<small>元 / 项</small>`。未定价用 `class="pv tbd"` + `待　定` |
| `table.res` | 单指标 + 三档色带定位条（TMAO 用的那种） |
| `table.resm` | 多指标分组表。`tr.grp` 分组头，`tr.ab` 标异常行，`<em>↑</em>` 箭头 |
| `.res-wrap.big` | 指标超过 10 行时套上，自动压缩行距 |
| `.tiers` | 三档解读块，3 列 |
| `.pbreak` | 断页。屏幕版显示裁切虚线，打印时隐藏 |

配色变量在 `assets/base.css` 顶部：`--deep` 深蓝、`--teal` 主色、灰区 `#B26A00`、异常 `#C0504D`。
**不要改字号、行距、配色**，19 份必须一致。

## 四、文案口径

看过 4 份 sheet 就知道调子了，几条硬规则：

- **一句话卖点用破折号点破一个常见误解**。「血脂正常不等于血管没风险」「抗氧化补了这么久，到底有没有用」「一半风险写在基因里，另一半写在基因的开关上」。不要写成产品广告词。
- 「可以做什么」三栏各配一个**两字动词**做标签：减源/改道/代谢、止损/对冲/增效、定位/控源/增益、预警/避雷/减负。动词要贴着这个项目的机制走，不要套用。
- 每栏结构固定：`<i>` 里是原理和为什么值得做，`<i>` 外是具体动作。
- 结尾 `.actnote` 给复查周期。**基因类项目不写复查**——终身不变，改写「在正确的时间点被想起」。
- 「与相关检查的区别」是防止销售把项目讲成二选一的地方，能交叉引用同系列其他项目就引用（用清单里的正式名称）。
- 不写「值得注意的是」「需要强调的是」这类空话。句子短，直给。

## 五、命名和编号

- 文件名 `NN_系统编号_协议项目名.html`，`NN` 是 manifest 顺序号。
- `.mast` 和 `.hero h1` 里的项目名 **一字不改照抄 `项目清单.md`**。协议里的名字可能和实际内容对不上（比如「阿尔兹海默症抗体4项」其实测的是 Aβ 和 p-tau 不是抗体），**照抄，然后在交付时口头提一句**，不要自作主张改。
- 系统编号：内分泌 / 营养 / 代谢 / 环境毒素 / 免疫 / 神经 / 血栓 / 分子筛查 / 胃肠，各自从 01 起。

