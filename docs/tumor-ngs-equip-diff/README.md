# 设备清单变更对照（9.13 vs 9.12）

比对两份只含附件一设备清单的 Word：底稿 9.12 版（szwzf，60 行／104 台件），
本稿 9.13 版（郭鹏达，70 行／106 台件）。输出是在 9.13 版上标色的对照稿。

## 9.13 版带修订标记

郭鹏达的稿子里留着未接受的 tracked changes。直接抽文本会把删除与插入的内容连在
一起（出现「温湿度计计时器」「数量 11」这类拼接），比对结果全是假差异。

`dumprev.py` 因此按修订感知抽取：`mode='final'` 丢掉 `<w:del>`（接受全部修订），
`mode='orig'` 丢掉 `<w:ins>` 并把 `<w:delText>` 当正文（拒绝全部修订）；整行的
新增／删除看 `<w:trPr>` 里的 `<w:ins>`／`<w:del>`。

一个容易踩的坑：`<w:t[^>]*>` 会匹配上 `<w:tcPr>`，把整段单元格属性 XML 当成正文
取出来。正则必须写成 `<w:t(?:\s[^>]*)?>`。

顺带一提，郭稿「原稿」态是 58 行，而 szwzf 版是 60 行 —— 两者并非同一基线，所以
比对用的是**两边的终稿**，不是郭稿内部的修订对比。

## 分区结构：8 间 → 9 间

| 9.12 版 | 9.13 版 | 变化 |
| --- | --- | --- |
| PCR4 破碎区 ＋ PCR5 文库制备区 | **PCR4 文库制备区** | 两间合并 |
| — | **PCR5 扩增一区** | 原 PCR5 腾出，改作文库预扩增 |
| PCR7 扩增区（捕获后扩增＋上机前质检） | **PCR7 扩增二区**（捕获后扩增） | 质检移出 |
| — | **PCR9 电泳** | 新增，承接上机前质检 |

其余四间（试剂准备间、PCR2、PCR3、PCR6、PCR8）分区名未变，PCR6 的步骤加了「纯化」。

## 逐行归类

`cmp_equip.py` 按 PCR 编号对齐两版的分区，再逐行归类为 未变／修改／调入／新增，
并单独列出移出本区的设备。

移出的判定有个噪音问题：移液器、计时器、温湿度计这类通用器具几乎每间都有，逐间
报「移出→PCR2/3/4/6/7/9」毫无信息量。脚本因此设了 `GENERIC` 集合，只报专用仪器
的真实迁移——本次只有一条：全自动毛细管电泳仪 PCR7 → PCR9。

结果：未变 51、修改 6、调入 9、新增 4。

## 待补项

9.13 版新填的 9 行里有 8 行**厂商与规格型号为空**，集中在 PCR4（PCR扩增仪、漩涡
振荡器、掌式离心机、磁力架、计时器、温湿度计、生物安全柜）与 PCR5（计时器）。
对照稿用「待补」标记标出。PCR5 的计时器是原有行被清空，归为「修改」而非「新增」。

另外 PCR4 的生物安全柜（A2 型）**用途列为空**，PCR6 与 PCR7 各有一整行空行，
对照稿已跳过空行不计入 70 行。

## 颜色

绿＝新增，紫＝由其他分区调入，黄＝参数或数量修改（表内注明原值），红＝移出本区，
无底色＝未变。HTML 与 Word 用同一组色值；Word 通过 `<w:shd w:fill>` 上底色，构建
脚本回读 docx 校验五种底色是否都真的写进去了。
