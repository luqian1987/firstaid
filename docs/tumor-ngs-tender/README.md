# 肿瘤 NGS 平台招标需求（对外稿）

面向投标人发布的招标需求。核心是一套采购：**基因测序仪 1 台 + 配套设备与器具
+ 检测试剂**。

## 对外与对内的分界

这份文件与院内汇报材料是同一件事的两个面。院内材料讲清楚现状与判断，招标文件
只写投标人需要知道的。因此本稿刻意不出现：具体科室名称、房间编号、拟选平台的
品牌型号、内部会议的决策过程与分工、以及尚未定案的内部安排。

`build_tender.py` 用断言把这条守住：品牌名、科室名、房间号、内部会议措辞一旦
出现即报错。「折扣率」是本文件的正当用语，只有单独出现的「扣率」（参照文本中的
供应商报价扣率）被禁止。

## 文件的边界

采购需求描述「买什么、达到什么标准」；付款比例、违约责任、退出交接、资格
审查的标准条款属于招标文件的合同章节或采购部门的通用模板，不在需求文件内。
初稿把这些一并写了，等于在需求阶段提前锁死合同谈判空间。现已收回：付款只
留一句原则（设备款验收后一次性支付、试剂款按实际供货结算，账期合同约定），
质保期限与响应时限交由合同约定，删去违约与退出整节，资格条件收到四条基本项。
文末保留一句「未尽事宜以招标文件其他章节及采购合同约定为准」作为兜底。

## 收窄的方式

需求收得太开放会引来过多投标人，但用通量、读长等数字收窄等于照着某台机器
量身定制，最易被质疑。本稿改用**组合式条件**：每一条都能用一句临床或管理
理由说清，指向需求而非品牌，叠加后才形成真实门槛。

| 条件 | 理由 |
| --- | --- |
| 三个癌种**分别**列明对应注册试剂盒，并提供注册证复印件 | 首批就要开展三个癌种，泛实体瘤产品不能替代 |
| 建库采用**杂交捕获富集法** | 中大 panel 需同步检出融合与拷贝数变异 |
| 同时支持**组织 FFPE 与血浆 cfDNA** | 实验室设有血浆文库制备区，缺此能力即空置一间 |
| **整包投标**，不接受分包与联合体 | 责任单一、接口统一、验收与售后可追溯 |
| 业绩须能提供合同或验收证明 | 空口业绩不可核 |

**测序仪不写机型参数。** 通量、读长这类数字写死就是换个方式定向。本稿改为资质
加功能性指标，关键是第 3 项「配套试剂的注册匹配」：要求所投测序仪具备已注册、
且注册证载明适用机型包含该机型、注册适用范围覆盖拟开展癌种的试剂盒。这是从
临床需求出发的正当门槛，不指定品牌，但门槛是真实的。

**场地留有余地。** 不写「不涉及改造」，改为中标人负责设备就位所需的台面承重等
局部适配调整，费用计入报价。

**清单全部供应。** 设备最终将整体迁至分子诊断中心，该处无既有设备，因此不设
「沿用院方现有设备」的口径：附件一所列由中标人全部供应，并明确投标人不得作
缺项或以「院方自备」方式排除。

**检测项目只写核心必检基因。** 把一个癌种的靶点逐个列全，等于把 panel 的组成
描述出来，投标产品少一个靶点就不合规 —— 这是换个方式定向。附表 2 只保留各
癌种指南层面的核心必检基因，并在表下注明「属最低检测范围要求，覆盖更多靶点
的产品不因此受限」。

初稿曾在结直肠癌一行写入 MSI／错配修复，那是起草时自行添加、并非来自任何
来源材料，且方法学不符：国内 MSI 的注册产品以多重荧光 PCR-毛细管电泳法为主
（首证为国械注准20213400070），并非高通量测序，写入 NGS 平台招标需求会使
投标人无法以有证产品应答。已删除，并在 `build_tender.py` 中设为禁用词。

**移机服务列为可选报价项。** 设备将来要整体迁走，拆装复位与迁后重新性能验证
的费用若不预先约定，届时只能按合同外服务另议。商务要求第（五）项要求投标人
单独报出移机服务价格，作为可选报价项，不计入评标价，中标后由院方决定是否
实施；并明确移机不影响原质保期的连续计算。

**试剂纳入采购，以折扣率报价**，基准价取厂家挂牌价或省级平台挂网价，原则上不
高于五折；性能验证不通过的产品须更换，费用与延误由中标人承担。

## 文件

| 文件 | 说明 |
| --- | --- |
| `ngs-tender.html` | 成品，黑白 A4 版式，浏览器可直接打印 |
| `tender_head.html` / `tender_body.html` | 样式头与正文模板 |
| `build_tender.py` | 生成 HTML，含守卫 |
| `build_tender_docx.js` | 生成 Word 版，运行前自动调用 `export_docx_data.py` 重导数据 |
| `export_docx_data.py` | 从 `build_tender.py` 现场导出 Word 版所需数据 |
| `readdoc.py` | 从 OLE2 格式的 .doc 提取正文（本容器 LibreOffice 不可用） |

## 已知限制

docx-js 生成段落边框时子元素顺序与 OOXML 要求冲突，同时带上下框线的段落无法
通过 schema 校验；如需框线段落，改用单格表格。本容器 LibreOffice 无法启动，
Word 版仅通过 XML schema 校验与结构回读，未做渲染视觉复核。
