# 肿瘤 NGS 平台招标需求（对外稿）

面向投标人发布的招标需求。核心是一套采购：**基因测序仪 1 台 + 配套设备与器具
+ 检测试剂**。

## 对外与对内的分界

这份文件与院内汇报材料是同一件事的两个面。院内材料讲清楚现状与判断，招标文件
只写投标人需要知道的。因此本稿刻意不出现：具体科室名称、房间编号、拟选平台的
品牌型号、内部会议的决策过程与分工、以及尚未定案的内部安排。

`build_tender.py` 用断言把这条守住：品牌名、科室名、房间号、内部会议措辞一旦
出现即报错。「折扣率」是本文件的正当用语，只有单独出现的「扣率」（参照文本中的
供应商报价扣率）被禁止。

## 试剂报价与物价挂钩

试剂报价不采用「厂家挂牌价 × 折扣率」：挂牌价由厂家自定、院方难以核验，且一旦
锁定折扣率，收费政策调整时价格无法随动。改为以**所对应检测项目的收费标准**为
基准，投标人所报单价不高于该收费标准的一定比例，比例在服务期内固定。

现行收费按编码 012100000200000「高通量测序法检测费（病理样本）」分档，为
4,500 / 7,000 / 9,900 元三档（来源：《可开展检测项目与收费》，5 个试剂盒中
4,500 元 3 个、7,000 元 1 个、9,900 元 1 个）。具体产品适用哪一档，以物价备案
结果为准，故正文只写机制、不写数字，档次作为参考列于附件二注。

这一改法同时消化了价格政策调整的时点风险：国家医保局已发布检验类医疗服务价格
项目立项指南并要求各省对接落地，江苏落地后收费标准若变动，试剂单价按同一比例
随动，无须重新协商，因此原「政策衔接」条款可以删除，文件也不必解释政策背景。

## 文件的边界

采购需求描述「买什么、达到什么标准」；付款比例、违约责任、退出交接、资格
审查的标准条款属于招标文件的合同章节或采购部门的通用模板，不在需求文件内。
初稿把这些一并写了，等于在需求阶段提前锁死合同谈判空间。现已收回：付款只
留一句原则（设备款验收后一次性支付、试剂款按实际供货结算，账期合同约定），
质保期限与响应时限交由合同约定，删去违约与退出整节。

**投标人资格与合规整节亦已删除。** 资格审查、评审办法属招标文件的独立章节，
由采购部门按通用模板出具；需求文件里写一份自拟的资格条件，既无约束力，又可能
与正式招标文件冲突。同样删去的还有「不计入评标价」「作为评审因素」这类评标办法
措辞 —— 需求文件不规定怎么评。两版文末各保留一句：「本文件为采购需求／建设需求，
仅描述本项目的技术与商务需求。投标人资格条件、评审办法、合同条款及其他未尽事宜，
以招标文件相应章节及采购合同约定为准。」

## 收窄的方式

需求收得太开放会引来过多投标人，但用通量、读长等数字收窄等于照着某台机器
量身定制，最易被质疑。本稿改用**组合式条件**：每一条都能用一句临床或管理
理由说清，指向需求而非品牌，叠加后才形成真实门槛。

| 条件 | 理由 |
| --- | --- |
| 三个癌种**分别**列明对应注册试剂盒，并提供注册证复印件 | 首批就要开展三个癌种，泛实体瘤产品不能替代 |
| 建库采用**杂交捕获富集法** | 中大 panel 需同步检出融合与拷贝数变异 |
| 同时支持**组织 FFPE 与血浆 cfDNA** | 实验室单设样本制备区（血浆），缺此能力即空置一间 |
| **整包投标**，不接受分包与联合体 | 责任单一、接口统一、验收与售后可追溯 |
| **所投产品应为本国产品**，不接受进口产品投标 | 《政府采购法》第十条规定政府采购应当采购本国货物；采购进口产品须事先论证核准 |
| 检测数据存储于院内，**不得上传院外、不得出境** | 《人类遗传资源管理条例》及数据安全相关要求 |

**测序仪不写机型参数。** 通量、读长这类数字写死就是换个方式定向。本稿改为资质
加功能性指标，关键是第 3 项「配套试剂的注册匹配」：要求所投测序仪具备已注册、
且注册证载明适用机型包含该机型、注册适用范围覆盖拟开展癌种的试剂盒。这是从
临床需求出发的正当门槛，不指定品牌，但门槛是真实的。

**场地留有余地。** 不写「不涉及改造」，改为中标人负责设备就位所需的台面承重等
局部适配调整，费用计入报价。

**清单全部供应。** 设备最终将整体迁至分子诊断中心，该处无既有设备，因此不设
「沿用院方现有设备」的口径：附件一所列由中标人全部供应，并明确投标人不得作
缺项或以「院方自备」方式排除。

**检测项目只写核心必检基因。** 把一个癌种的靶点逐个列全，等于把 panel 的组成
描述出来，投标产品少一个靶点就不合规 —— 这是换个方式定向。附表 2 只保留各
癌种指南层面的核心必检基因，并在表下注明「属最低检测范围要求，覆盖更多靶点
的产品不因此受限」。

初稿曾在结直肠癌一行写入 MSI／错配修复，那是起草时自行添加、并非来自任何
来源材料，且方法学不符：国内 MSI 的注册产品以多重荧光 PCR-毛细管电泳法为主
（首证为国械注准20213400070），并非高通量测序，写入 NGS 平台招标需求会使
投标人无法以有证产品应答。已删除，并在 `build_tender.py` 中设为禁用词。

**移机服务列为可选报价项。** 设备将来要整体迁走，拆装复位与迁后重新性能验证
的费用若不预先约定，届时只能按合同外服务另议。商务要求第（五）项要求投标人
单独报出移机服务价格，作为可选报价项单独列示，由院方按实际需要决定是否
实施；并明确移机不影响原质保期的连续计算。

## 功能分区改为八间（2026-09-11 更新）

设备清单换为 `20260911` 版的 **Sheet2**（重新分区表）。原六间布局把片段化放在
标本与文库制备区内部（「划区不划间」）；新布局把**破碎区独立成间**，并因此启用
了原先跳过的两间房，全表由 6 间扩为 8 间：

| 分区 | 步骤 | 行数 / 台件 |
| --- | --- | --- |
| 试剂准备区 | 试剂配制与分装 | 8 / 13 |
| 样本制备区（组织） | 组织样本处理与基因组 DNA 提取 | 12 / 20 |
| 样本制备区（血浆） | 血浆分离与游离 DNA 提取 | 14 / 22 |
| 破碎区（核酸片段化） | 基因组 DNA 片段化 | 2 / 2 |
| 文库制备区 | 末端修复、接头连接与文库构建 | 11 / 19 |
| 杂交捕获区 | 探针杂交与磁珠捕获 | 15 / 24 |
| 扩增区 | 捕获后扩增与上机前质检 | 10 / 15 |
| 测序区 | 上机测序与数据分析 | 3 / 3 |

合计 75 项、118 台（件），不含测序仪（测序仪在正文单独成章）。

独立成间的由来：《宏基因组高通量测序技术临床实验室规范化应用指南》对**超声打断**
建议单独设置打断区，酶法片段化则作为文库制备区内的一个步骤即可。原方案按酶法
设计，故无片段化设备；新清单引入超声片段化，相应把破碎区独立出来。

**这一条在对外稿里必须写成方法学中立的**，否则等于指向某一家的工艺路线。表 1
第 4 项因此写为：片段化「采用酶法或物理超声法均可，本项目不作限定」；附件一已
按物理超声法预留设备与独立分区，投标人按所投试剂盒的实际方法学一并供应并提出
安装条件。这样超声路线的设备有出处，酶法路线也不会因此不合规。

### 去品牌与合并规则

`extract_equip2.py` 负责把原始清单转成对外口径：

- 只取「设备名称 + 参数要求」，丢弃「产品名称」列（该列全是品牌型号）；
- 参数要求中夹带的型号一并清洗（超净工作台的 ACB-1300V、片段化仪的机型名等）；
- **同一分区内同名器具合并为一行、数量相加**。原清单里有两套互不通用的磁力架和
  两台不同的荧光计，去品牌后描述相同，合并计数既不失真也不暴露工艺路线差异；
  正文已要求投标人逐项应答所投产品的品牌与型号；
- 磁力架按管型拆为三类（1.5 mL 管用 / 5 mL 管用 / 96 孔），避免合并掉真实差异；
- 脚本对未定义参数描述的设备名直接报错，新增设备不会被静默带上默认值。

### 一台测序仪与两条工艺路线

新清单里成对出现的器具（两套磁力架、多台原厂荧光计、一台独立生信服务器、一台
真空离心浓缩仪、一台超声片段化仪）说明清单是按**两家试剂盒的工艺路线叠加**而成
的，不是在原方案上补一台片段化仪。但清单里**测序仪仍只有一台**。

这一点在对外稿里无法解决，只能由院方在定案前确认：现有 5 张注册证中，一张为
联合探针锚定聚合测序法，其余四张为可逆末端终止测序法，两类化学互不通用。若最终
只采购一台测序仪，则试剂盒的可选范围被机型锁定；若两条路线都要跑，测序仪数量与
预算需要重新核定。表 1 第 2 项「测序原理：不限」与第 3 项「注册证载明的适用机型
应包含所投机型」已把这个约束显性化 —— 投标人必须自证其试剂盒与其所投机型匹配，
不匹配的组合在应答阶段就会暴露。

### 原始清单中需要院方确认的两点

- **Sheet2 没有不间断电源（UPS）**，Sheet1 有。测序仪与分析服务器断电保护通常
  需要，附件一按 Sheet2 照录未加。表 1 第 8 项要求投标人说明是否需要配置 UPS，
  暂由此兜底。
- **破碎区只有掌式离心机与片段化仪两件**，无温湿度计。其余七间均配温湿度计用于
  环境记录。按清单照录，未自行添加。

## 第三个体例：对院应答稿（不隐去品牌）

前两版是对外发布稿，刻意不出现品牌与内部安排。院方给的参照文档本身并不隐去
任何东西 —— 它直接列 Illumina NextSeq 550DX、华大智造 MGISEQ-200／MGISEQ-2000
三台测序仪，也直接写金域 48%、迪安 54% 的扣率。既然是对院答复，就没有必要
套那层合规措辞。

`ngs-ref.html` 逐节照搬参照文档的骨架：测序仪表 → 服务内容（按条编号）→
人员规划 → 科研支持 → 应急事件表 → 报价表 → 附件一设备清单（房间｜步骤｜
产品名称｜建议厂商｜建议规格型号｜数量｜用途）。与前两版的差别：

- **测序仪明写华大智造 MGISEQ-2000，1 台**；服务内容第 2 条据此要求试剂盒
  注册证载明的适用机型包含 MGISEQ-2000；
- **附件一保留品牌与型号**，由 `extract_equip_raw.py` 从原始清单生成：产品名称
  取通用设备名，厂商与型号从原「产品名称」列拆出，同房间同名器具合并计数、
  厂商与型号并列显示（如磁力架一行显示「碳环智造／世和（定制）」）；
- 房间列用真实房号（PCR2…PCR8），步骤列按分区填写；
- 参照文档的「意向公司」表改为「报价」表，公司名称、试剂比例、质保年限留空待填。

### 按肿瘤 NGS 的实际重写，不逐字照搬

参照文档是给感染病原学 mNGS 外送模式写的，有几处放到肿瘤 NGS 上不成立：

**删去「负责标本运输和冷链物流」整条。** 原文承诺专人专车服务一院五区、归拢
30+ 社区卫生院样本。本项目检测集中在总院区完成，院区间样本的收集与转运属院方
自管范围，我方只提供总院区的检测平台与试剂。试剂冷链并入服务内容第 2 条：
全程冷链配送至太湖新城总院区实验室。

**应急事件表整表重排。** 原表五类事件里，「危重病人处理应急」（危急值优先检测、
电话通知到位）是即时检验项目的逻辑 —— 肿瘤 NGS 报告以日计，不存在危急值；
「物流运输应急」随上一条一并删去；「医疗纠纷应急」改为「检测结果争议与复核」，
更贴近本类项目的真实争议形态（结果与临床或既往病理不符）。新增两类本项目最高频
的中断来源：**样本质量不合格或建库、捕获失败**（FFPE 样本 DNA 降解、肿瘤细胞
含量不足）与**检测报告超期**。`build_ref.py` 把删去的几项设为禁用词，防止后续
改稿时又被照抄回来。

**性能验证指标改为 NGS 口径**：精密度、正确度、最低检出变异频率、测序深度与
覆盖均一度、可报告范围。原文的「检出限」对 NGS 不够具体。

**驻场人数改为前期 1–2 名**，按院方实际需求与样本量调整（服务内容第 4 条与
人员规划两处同步）。

两处与参照文档刻意不同：

**科研支持一节保留，但写成拒绝绑定。** 参照文档在此处写「合作期内提供一名驻场
科研人员（博士学位……）协助医院发表文章与撰写标书」。以科研资源作为采购的
附带条件，与《医疗机构工作人员廉洁从业九项准则》关于不得收受与业务相关的
不正当利益的要求存在冲突，且此前同类项目签约时并未约定此项。本稿该节改为
明确不设科研绑定条款，另有科研合作意向则另行立项、单独签署、与采购不关联。

**应急事件表加了一行「数据或分析系统应急」。** 参照文档的五类应急事件针对的是
外送检验模式；本项目分析解读在院内本地化部署，数据完整性与系统可用性是新增的
风险点。

### 一台测序仪装不下五张注册证

参照文档列三台测序仪不是冗余配置 —— 现有 5 张可用注册证里，1 张是联合探针锚定
聚合测序法（MGI 化学），4 张是可逆末端终止测序法（Illumina 化学），两类互不
通用。本稿按要求只写 MGISEQ-2000 一台，代价是可用试剂盒被机型锁定为前者。
故本稿不设「拟开展检测项目」一节（参照文档同样没有），避免出现「首批开展三个
癌种」与「只有一张证能用」的自相矛盾。这一点须由院方在定案前确认。

## 两个体例

同一套需求，两种呈现，供院方选用：

| 体例 | 文件 | 结构 |
| --- | --- | --- |
| 采购需求 | `ngs-tender.html` | 一、项目概况／二、测序仪技术要求／三、配套设备／四、检测试剂／五、服务要求／六、商务要求＋两个附件 |
| 服务内容 | `ngs-plan.html` | 测序仪／服务内容（七条）／人员规划／应急事件对接和处理／拟开展检测项目／报价要求＋设备清单 |

服务内容体例对齐院方此前收到的同类文件的骨架 —— 表格在前、服务内容按条编号、
人员与应急单列、设备清单带「步骤」与「用途」两列 —— 便于对照阅读；但原骨架中
的意向公司报价、科研支持、项目推广、指定品牌等内容均未沿用。两版数据同源，
`build_plan.py` 直接引用 `build_tender.py` 的技术要求、检测项目与设备清单，
不存在两处维护。

| `苏州市立医院-肿瘤NGS平台招标需求（对院应答稿）.docx` | 对院应答稿 Word |
| `ref_body.html` / `build_ref.py` | 对院应答稿的正文模板与生成脚本 |
| `build_ref_docx.js` / `export_ref_data.py` | 对院应答稿 Word 版生成与数据导出 |
| `extract_equip_raw.py` / `equip_raw.json` | 带品牌型号的设备清单（房间｜步骤｜产品名称｜厂商｜型号｜数量｜用途） |

## 已知限制

docx-js 生成段落边框时子元素顺序与 OOXML 要求冲突，同时带上下框线的段落无法
通过 schema 校验；如需框线段落，改用单格表格。本容器 LibreOffice 无法启动，
Word 版仅通过 XML schema 校验与结构回读，未做渲染视觉复核。

## 交付格式

只交付 Word，不出 PDF。Word 可由院方直接编辑、批注与套用文头，PDF 在这个
场景下没有额外用处。HTML 保留为版式与内容的单一来源，Word 由脚本从中生成。
