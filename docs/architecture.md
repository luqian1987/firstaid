# 架构

## 为什么是这个形状

两种做法的差别不在提示词，在数据流向：

```
扇出式（内容生成）：
    指标 → 打箭头 → 归入主题 → 主题挂模板动作 → 用本人数值填槽
    指标之间从不相遇，所以永远发现不了矛盾。

收敛式（二次判读）：
    指标组合 → 识别形态/矛盾 → 生成判读 → 排序
    判断产生在指标的关系上，不在单个指标上。
```

本系统是后者。所有设计取舍都服从一件事：**判断必须产生在指标的关系上，且可回溯。**

## 分层

| 层 | 目录 | 职责 | 关键不变式 |
|---|---|---|---|
| L0 观察 | `model/observation.py` | 全部原始观察，带出处 | 无出处的观察不得进入判读 |
| L1 归一 | `normalize/` | 单位换算、别名解析、区间解析 | 解析不了 → NO_RANGE，绝不猜成正常 |
| L2 派生 | `derive/` | 派生指标 + 与原报告派生值的一致性校验 | 每个派生值带公式与输入 |
| L3 模式 | `patterns/` | 十类推理模式，三态求值 | 缺输入 → INDETERMINATE，不是未命中 |
| L4 组装 | `patterns/engine.py`, `assemble/` | 命中 → 判读链条 → 分章排序 | 不可改变的主线不得进可行动章 |
| L4.5 对账 | `assemble/reconcile.py` | 原报告每条结论 → 本次回答 | 结论无人回答 → 构建失败 |
| L4.7 深读 | `assemble/depth.py` | 通路 / 机制 / 修饰因素 / 干预 | 说不出判定指标的阶段 → 构建失败 |
| L5 审计 | `audit/` | 覆盖率保证 | 异常项无归宿 → 构建失败 |
| L6 表达 | `render/` | 叙述与渲染 | 文本中的数字必须可追溯到 evidence |

## 对账层：原报告说的每一条，都要有回答

系统一开始只读检验值，不读报告怎么说。结果是它只能自说自话——
客户手里那份"医院说我有 19 条问题"的清单，一条也没被正面回答。

`OriginalFinding` 是提取层要抽的第二类东西（第一类是检验值）：
半结构化文本 `【检查项目】结论 →（1）建议……`。它声明自己涉及哪些指标，
判读链条声明自己用了哪些指标，对账取两者交集——机械匹配，不靠手工连线。

两条不变式：

- **每条原报告结论都必须有回答。** 找不到就是规则库漏了它，构建失败。
  标注"报告自取/详见附件"的条目例外，它们进边界。
- **同一件事只讲一遍。** 多条原报告条目落到同一个判读上时合并成一行。
  原报告把"体重指数高"和"脂肪肝 + GGT 高"分成两条给建议，那本来就是一件事。

## 对外只暴露三条色带

内部的 `Chapter`（7）× `Tag`（7）分级不变，但不再往外抛——
读者不该先学一套分类法才能读报告。`Band` 只有三档，判据是"接下来做什么"：

| 色带 | 含义 |
|---|---|
| 现在要做 | 已经确定，而且有明确的入口 |
| 先弄清楚 | 事实还不牢，先复测或先补一项背景 |
| 可以放下 | 查过了，本次不需要占用精力 |

`◇ 与医生确认` 是叠加在色带上的标记，不是第四种分类。
`Tag → Band` 是确定性映射，有测试锁死。

## 措辞：我们不是接诊医生

每条纠正带两套说法：`claim` 是内部精确说法（用于日志与审计），
`claim_soft` 是对外措辞——陈述发现 + 请求确认，不判原报告的对错。
类型层强制 `claim_soft` 非空，测试禁止其中出现"不成立""错了"这类判定性表述。

## 深读层：四块内容，一条共同约束

**写不出引用本人数据的内容，不许出现在报告里。**

| 块 | 回答什么 | 约束 |
|---|---|---|
| 机制支点 | 为什么这组数据指向这个方向 | `Mechanism.cites` 非空。写不出引用的机制是教科书内容 |
| 通路阶梯 | 离不良结局有多远 | `PathwayStage.judged_by` 非空；每一关的状态由表达式对本人数据求值 |
| 修饰因素 | 影响力有多大 | 三分法：在场 / 已排除 / 未知。不给权重系数，给可核对的清单 |
| 干预 | 这一条能做什么 | 非临床类必须声明 `verify_by`；临床类只写路径与该问什么 |

通路那条约束顺带解决了"远端病名吓人"的问题：我们对肝硬化、胃癌这些阶段一个指标都没有，
所以它们**自动画不出来**，不需要靠人记得删。同理，图上禁止出现任何时间预测——
"多久到下一关"需要队列数据来校准，我们没有，写年数是编造。构建期用正则拦截。

**进图判据**（三条全中才进，缺一条即排除）：

1. 它描述的是一个**会沿方向演变的过程**——不是静态状态、不是检测口径问题、不是来源问题；
2. 该过程上**至少有一关本系统有指标能判定**；
3. **至少有一关的状态不是"判不了"**——整条都是虚线的图没有信息。

拓扑图自己也要声明覆盖率：行动档的每条判读，**要么在图上，要么在 `no_progression`
里写明为什么没有进展结构**，缺一个就是构建失败。

这条约束和这套判据都是被真实漏洞逼出来的。先是牙龈出血（「现在要做」档却没进图），
后是胃黏膜萎缩与脾功能亢进——三条都是**凭感觉排除、事后才发现判错**的。
判据写死之后，排除必须援引判据，测试会检查这一点。

**不在每章重画。** 每条判读只给一行定位（"现在在哪一关、下一关什么状态"）加锚点。
报告级那张图的价值在于跨路径比较——谁共享上游、哪条已落印——拆成单条就全没了；
重画一遍还会变成同一件事讲两遍。

拓扑图区分**共享上游**与**独立上游**（后者画虚线边框）。对本例：
肝脏与糖代谢共享"中心性脂肪"，血管出自"脂蛋白(a) 升高"且不共享——
这正是"同一个干预覆盖不到第三条"的依据。参考实现把这一点弄反了，
它把三条路径都归到胰岛素抵抗上，而本人三个独立指标都显示胰岛素抵抗未发生。

## 三条硬约束

**一、判断权归规则，措辞权归叙述器。**
模式触发与算术是确定性代码，可测试、可复现。LLM 只把已认定的事实写顺，
且只能引用规则传给它的数值（`render/narrate.py::verify_citations`）。
绝不让模型决定一个发现是否存在。

**二、原报告的区间和本系统的知识严格分轨。**
`Observation.ref/status` 永远只反映原报告给了什么；本系统补的常用切点走
`advisory_ref/advisory_status`，并记录出处。所以能如实说出
"原报告未给参考区间；常用切点 7.0 kPa 以下无明显纤维化"这两句话。

**三、覆盖率是断言，不是描述。**
每条观察恰好一个归宿：进链条 / 进需纠正 / 已降级 / 建基线 / 已确认良好 /
完整留档 / 登记为边界。异常项落进"未认领"就是构建失败。
这一层会主动暴露知识库缺口——某个异常反复无人认领，说明缺规则，不是数据特殊。

## 十类推理模式

模式是代码 + 测试，规则实例是纯数据。换一组指标不用改代码。

| # | 模式 | 判读形态 |
|---|---|---|
| 1 | `upstream_contradicted` | 上游异常，下游全阴 → 检测可信度存疑 |
| 2 | `corrected_vs_raw` | 校正值正常 → 未校正值的异常由已知混杂解释 |
| 3 | `paired_divergence` | 配对同向背离 → 系统性偏差而非两个独立异常 |
| 4 | `pattern_dissociation` | 单项升高与本该同行的指标脱节 → 指向不同病因 |
| 5 | `layered_exclusion` | 命名发现按层逐一排除 → 可降级 |
| 6 | `isolated_abnormal` | 孤立异常缺乏佐证 |
| 7 | `acute_phase_coherence` | 多个指标共同描述同一良性背景 |
| 8 | `normal_panel_hidden_risk` | 常规组套全正常，但组合提示风险 |
| 9 | `unranged_structural` | 无区间结构性发现 → 不判高低，转比较口径 |
| 10 | `range_kind_caveat` | 拿实验室自有百分位当疾病界值 |

第 10 类是覆盖率审计逼出来的：两项异常反复落进 UNRESOLVED，说明知识库缺规则。
这正是 L5 应有的作用。

## 纵向

"下次比什么"不是文案，是会被持久化的对象。

- `ComparabilityKey = (code, unit, method, device, axis)`，影像与弹性成像标 `device_sensitive`
- 每条判读产出 `ComparisonItem`，汇总成 `ComparisonPlan`
- 下次体检把新观察对到上次的 plan 上，比不了要说清为什么（换设备/换单位/换方法），而不是硬比

v1 只分析单次，但 `Subject → Encounter → Observation` 与 `Timeline` 现在就是一等对象。
单点分析会显式声明"没有既往体检数据，全部结论只是单点"。

## 责任边界（写进类型，不靠自觉）

- `Verdict` 缺 `not_certain` → 构造失败。不写边界的判读不许发布。
- `Correction.contradicting` 为空 → 构造失败。纠正原报告必须引用同一份报告内的反证。
- 纠正的措辞不说"报告错了"，只说"这条建议的依据不成立"；`what_to_do` 落到复测或面诊。
- 分章不变式：`Modifiability.NOT_MODIFIABLE` 的主线不得进"值得重视，也能主动改善"章。

## 回归集：每一份真实报告都要一直跑得通

`tests/fixtures/corpus.yaml` + `tests/test_corpus.py`

规则库是一次加一条长起来的。判断一条改动有没有把别人弄坏，唯一可靠的办法
是让它同时对着所有攒下来的真实报告跑一遍——每一份都要求覆盖率全绿、
原报告的每一条结论都有回答、且已去标识。

夹具文件加了却没登记进 `corpus.yaml`，测试失败；不作为回归案例的必须写明理由。
覆盖率断言在这一层的形式就是它。

第二份真实报告加进来时一次性暴露了五个错（见台账 L015–L019），
全是"换一个人才会犯"的错：规则引用了对方没做的检查、
规则引用了本系统判不了的指标而静默失效、上游判定条件按第一个病人写窄了、
以及一整类"发现在场但判据全缺"没有任何合法归宿。
这类错在单病例上永远不会出现。

第三份（L020–L028）带来的是三个此前完全没有的输入面：第一位女性受检者、
第一例自身免疫、第一次以"偏低"为主。它暴露的九个错里，有一族反复出现且
最值得警惕——**规则和文本可以断言模式层根本没检查过的东西**：
参数名写错被静默忽略、通路阶段的判据塞了不相干的指标、
"已排除"那一栏引用的指标其实是异常的、"本次未找到上游"后面跟着一句写死的解释。
它们的共同点是构建全绿而结论是错的。凡能变成断言的都已经变成断言；
剩下那半（叙述文本里的定性断言）只能靠一条流程约束：
**跨病例复用一条规则前，逐句重读它的断言**。

## 错误台账：每个错也要有归宿

`knowledge/lessons/lessons.yaml`

覆盖率断言的思路同样用在错误上。**每个记下来的错必须有归宿**——落在哪一层、
被哪条测试守着。台账里指向的测试如果不存在，`test_lessons.py` 报错，
台账就不会退化成一份没人看的文档。

修复层级，越靠前越有价值：

| 层 | 作用 |
|---|---|
| `invariant` | 构建期断言——让**整类**错无法通过构建 |
| `criterion` | 可援引的判据——让人的判断有依据，且"必须援引判据"本身又是断言 |
| `archetype` | 新增一类推理模式 |
| `knowledge` | 纯数据条目（规则/通路/本体/别名） |
| `hardcode` | 兜底。必须说明 `why_not_general`，否则测试失败 |

**只有前两层能防止同类再犯**，后三层都只修了这一个。所以遇到一个错，
第一个该问的不是"能不能泛化"，而是**"能不能变成一条会报错的断言"**——
不能，再问能不能变成判据；再不能，才轮到加知识条目。

有一类错不在医学层（YAML 把 `no:` 解析成布尔、正则误伤化验值），
它们泛化不成医学判据，但**能变成构建期校验**，所以落 `invariant` 而不是 `hardcode`。

台账里也记别人的错：参考实现把脂蛋白(a) 归进"可主动改善"章这一条（L014），
不是我们犯的，但同样值得一条不变式。
