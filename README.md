# firstaid · 体检报告二次判读

把彼此相关的指标放在一起判读，而不是逐项解释箭头。

常规体检报告做的是"单指标 vs 参考区间"的一次判读。本系统做二次判读：
跨指标的关联、比值、形态与矛盾识别，以及原报告建议的可信度复核。

## 它能得到什么

以内置夹具（42 岁男性，一次体检 + 两份附件，71 条观察）为例：

- **常规血脂四项全部正常，但本次最需要处理的一件事就在血脂里** —— Lp(a) 超上限，
  颈动脉干净而颅内 M1 段已出现狭窄。这条判读不可能由"逐项看箭头"得到。
- **ApoB 被原报告标为异常，本系统建议先别当真** —— ApoB 与非 HDL-C、
  ApoA1 与 HDL-C 两组配对同向背离，更像检测侧问题。同一个数，相反的行动。
- **原报告的 4 条建议按组合判读不成立** —— 补 B6、补叶酸、尿路感染就诊、
  血液粘稠随访。每条的反证都在同一份报告里。
- **7 项原报告没算、但数据够算的派生指标** —— 三条主要判读的依据正是这些数。
- **原报告 BMI 26.9，用身高体重反算是 26.47** —— 一致性校验抓出来的。

```
$ firstaid tests/fixtures/zhang_real_2026-03-30.yaml

【L2 派生指标】13 项（原报告未计算）
  HOMA-IR      1.34    ← 4.9 × 6.14 ÷ 22.5
  FIB-4        1.36    ← 42 × 36 ÷ (162 × √47)
  ...
  一致性校验：! BMI 原报告 26.9 vs 重算 26.47（相差 1.6%，warn）

【L4.5 对账】原报告 19 条结论 → 16 行回答（未拿到 4 份附件）
  ── 现在要做（3）──
  [原报告 12、15] 常规血脂正常，但脂蛋白(a) 与颅内狭窄合起来是本次第一优先
  ── 先弄清楚（3）── ── 可以放下（10）──
【L5 覆盖率审计】已确认良好 80｜进入判读链条 47｜进入需纠正 23…

构建通过：每一条观察都有归宿，分章不变式成立。
```

报告的骨架是一张**对账表**：原报告说了什么、我们的回答是什么，一行一条。
它同时也是目录。对外只有三条色带——**现在要做 / 先弄清楚 / 可以放下**——
内部的七章分级不再往外抛。

## 设计要点

三条硬约束，都写进了类型和测试，不靠自觉：

1. **判断权归规则，措辞权归叙述器。** 模式触发与算术是确定性代码；
   LLM 只把已认定的事实写顺，且只能引用规则传给它的数值。
   绝不让模型决定一个发现是否存在。
2. **原报告的区间和本系统的知识严格分轨。** 原报告没给区间就是"无区间"，
   本系统补的常用切点走独立字段并记录出处。
3. **覆盖率是断言。** 每条观察恰好一个归宿，异常项无人认领即构建失败；
   原报告的每条结论也必须有回答，找不到同样构建失败。
   这条约束会主动暴露知识库缺口——第 10、11 类推理模式都是它逼出来的。

详见 [docs/architecture.md](docs/architecture.md)。

## 目录

```
knowledge/            领域知识（数据，非代码。由领域人员维护）
  ontology/           指标定义、别名、单位、可改变性、常用切点
  derived/            派生指标公式
  rules/              规则实例：九+一类模式的具体应用
src/firstaid/
  model/              数据模型（L0–L2 + 判读/纵向/审计）
  ingest/             提取适配器契约（DeepSeek 可替换）
  normalize/          单位、区间、别名归一
  derive/             派生引擎 + 一致性校验
  patterns/           十类推理模式 + 规则引擎（核心）
  assemble/           分章与排序不变式
  audit/              覆盖率保证
  render/             叙述与引用校验
tests/                规则夹具 + 回归测试
```
